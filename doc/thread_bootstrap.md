# Browser Agent 新线程启动词

## 1. 使用目的

本文件用于在新 Codex 线程中快速建立正确上下文，避免被旧的细粒度设计拖回去。

## 2. 新线程核心前提

我们重新定义这个项目：

`Agent = LLM + Tools + Memory + Runtime`

其中：

- `LLM`
  - 负责规划、调度、选择高阶 tools、生成最终结果
- `Tools`
  - 封装规则、等待、重试、提取、过滤等脏活
- `Memory`
  - 只保留高价值结构化上下文
- `Runtime`
  - 负责状态机、循环、执行、校验、容错

## 3. 我们放弃的旧思路

我们不再采用以下主线：

- 让 LLM 决定细粒度 DOM 动作
- 扫描器承担大量业务语义
- 等待页面“完全 ready”
- 把搜索词生成交给主 LLM 自由发挥
- 在每个小步骤都调用 LLM

## 4. 当前新设计原则

1. LLM 只处理高价值语义任务
2. 高阶 tool 优先，低阶 tool 仅作为内部实现
3. 搜索词优先规则生成，必要时用小模型补全
4. 页面等待采用短等待 + 快速失败
5. 结构化提取独立成 tool
6. 基础过滤和截断由代码完成
7. 最终结果由 LLM 生成 Markdown 或总结文本

## 5. 新线程应优先回答的问题

1. 应该有哪些高阶 tools
2. Runtime loop 最小应长什么样
3. Memory 最小结构是什么
4. 当前代码如何最小代价迁移到新主线
