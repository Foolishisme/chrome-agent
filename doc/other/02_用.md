# 二、Driver 用（驭模篇/战略层）：由"体"推导出的四大战区兵法

> **定位**：本层是面向“使用者”的战略方向。适用于日常开发、业务使用，以及利用现成 Agent 产品（如 Cursor、Manus）完成短期闭环任务的场景。
> 所有的战略，本质上是人类指挥官在 `Agent = LLM + Memory + Tools` 以及最脆弱的 `Human`（人类注意力与主观视角）四大核心战区上的兵力部署与防御切割。

---

## 🏛️ 战区一：记忆轴
> **战略目标**：对抗熵增定律与信噪比衰减。管好给系统喂什么形态的数据，保证每一滴流入的信息水分都被榨干。

### 用 04｜上下文治理

**源自**：体 05（信噪比衰减）+ 体 06（深广不可兼得）+ 体 14（工具动态演进）

**战略逻辑**：

- 代码库是低效的 AI 上下文载体。但 2026 年 IDE 已内置 AST 感知索引，**日常文件级精准挂载已是机器自动行为**。
- 人类的真正职责从"手动选文件"升级为 **"绘制地图"**：设计索引锚点与全局约束文件，确保机器的自动索引不会迷路。

**战略目标**：人类负责定义"检索边界与策略"，机器负责执行"精准检索与挂载"。

---

### 用 07｜会话生命周期管理

**源自**：体 11（上下文熵增）

**战略逻辑**：

- 每个 Session 都有有效生命周期，超过后历史噪音的伤害 > 历史经验的增益。
- 任务粒度 = Session 粒度。一个模块完成 → Session 关闭。不允许带着残留上下文开始新任务。

**战略目标**：用主动的"短暂遗忘"换取持续的高质量输出。

---

### 用 09｜低摩擦格式优先

**源自**：体 07（格式摩擦力）+ 体 01（Transformer 本质——它就是靠 Token 运行的）

**战略逻辑**：

- 向 LLM 输入高摩擦格式（PDF/Word/PPT），等效于在信号上叠加格式噪音——不仅浪费 Token 容量，还降低内容理解精度。
- 所有与 AI 交互的信息通道，必须优先使用 LLM 原生友好的结构化标记语言。

**执行标准**：

| 场景 | 正确格式 | 错误格式 |
|---|---|---|
| 需求文档给 AI | Markdown spec.md | PDF PRD |
| 数据结构定义 | JSON Schema / Protobuf | Word 表格截图 |
| 架构图给 AI | Mermaid / SVG | PPT 导出的 PNG |
| 日志分析 | 纯文本 / CSV | 截图 |

**战略目标**：消除人类与 AI 之间的格式摩擦，让每一个输入 Token 都承载最大信息密度。

---

### 用 10｜高信噪比命名法则

**源自**：体 05（信噪比衰减）+ 体 06（深广不可兼得）

**战略逻辑**：
- 在传统开发中，命名只需"人能看懂"。但在 AI 编程中，**命名更需要"机器能精准搜索"**。
- 如果将类命名为泛指的 `user` 或 `config`，当 Agent 在项目中调用检索工具查找用例时，会命中成百上千个无关文件。**这会瞬间引爆上下文噪音，并极大地消耗 LLM 宝贵的注意力资源** 去区分同名词（是 DB User 还是 UI User？）。

**战略目标**：废除泛指命名，强制使用具备全局唯一边界的强语义组合命名（如用 `UserAuthService` 代替 `UserService`，用 `fetchPaymentConfig` 代替 `getConfig`），从而在物理层降低 LLM 的检索噪音与认知负担。

---

### 用 11｜文档即状态

**源自**：体 16（跨会话失忆定律）

**战略逻辑**：
- 为应对大语言模型单次 Session 的记忆闭环强制清零，必须在物理界进行对抗性保存。这就如同将短效存储器写入数据库文件。
- **降伏人际与人机的高摩擦损耗**：不仅仅是机器没有连续记忆，在真实场景中，人与人的口口相传、人与大模型的随口碎片化对话同样潜藏着惊人的语义磨损与理解错位。
- 完全依托显性的文档文字沉积，不再幻想模型自动悟透内涵，强行把隐晦沟通降维固化为各方无法抵赖的标准契约。

**真理源优先级**：

1. **`spec.md` / `constraints.md`**：定义全局目标、硬约束、禁区，拥有最高优先级
2. **`plan.md` / `checkpoint.md` / ADR**：记录当前方案、状态流转和阶段性决策
3. **命名 / 注释 / 入口地图**：只负责降低查找摩擦和提升 Grep 命中率，不得反向改写全局约束

> 若三层信息冲突，以 `spec.md` / `constraints.md` 为准，并回写清理漂移

**战略目标**：让结构化文档身披双甲——既是抗击大模型失忆症的静态磁盘，也是熨平人造语言高损耗交流摩擦力的真理镇舱石。

---

### 用 13｜外部真理强注

**源自**：体 15（认知时滞定律）+ 体 04（幻觉不可消除）

**战略逻辑**：
- 对于非陈旧类库或者长久已存在的基础常识，在时间坐标越靠近当下、变动频率越剧烈的场景任务中，将其判定其默认处于“时效缺失”黑洞是安全的铁律防线防患。
- 只有向 AI 沙盒提供由人类发起或由主动联网搜集而来的准确原始官网/外部核心信源，方可彻底推翻它的时空偏差错觉缝合。

**战略目标**：全面废黜在面对最新的特性版本、新工具引入和动态变更策略时的内部模型脑补依赖，实施物理层面的强制信息网路抓取。

---

### 用 14｜无情裁剪与缓存对齐

**源自**：体 18（硅基注意力负载定律）+ 体 05（信噪比衰减）

**战略逻辑**：
- 任何无法直接服务于当前目标推演的冗长日志、前序无效试错过程的代码，都是在疯狂掠夺 LLM 宝贵的注意力配额。
- 只有将前缀指令做到极致固化与对齐，才能在降低算力花费的同时，让模型借由 KV Cache 极速且集中地命中目标逻辑。

**战略目标**：像手术刀一样切割发给环境与大模型的数据流，把易变量后置保障缓存，同时在外部拦截冗长记录，绝不让无效 Token 干扰大模型的算力聚焦。

---

### 用 23｜脱水事实前置战略

**源自**：体 27（事实重于逻辑） + 体 15（认知时滞） + 体 04（幻觉不可消除）

**战略逻辑**：
- 混在长文本消息（如网页搜索结果、PDF 研报）中的情绪、偏向性预测和 PR 辞令是极高浓度的逻辑噪音。
- **搜索的双面性**：自动搜索工具是一把双刃剑。它在精准抓取事实数据的同时，无可避免地会将网页广告、SEO 废话和其他衍生杂质一并拖入上下文，造成严重的隐性污染。
- 如果让推理模型（Pro 类）同时处理“阅读充满噪音的长文”与“分析判断”，其心智极易被文本中的形容词与无关信息锚定，产生“乐观偏差”。

**战略目标**：实施"信息脱水、事实先行"策略。在推理启动前，先调用低成本模型（Flash）充当无情的滤网，将外部搜索信源强行转化为无感情、无形容词、无广告预测值的 Markdown 事实表。

**操作升级：信源层级前置（先收窄，再脱水）**

脱水是对已获取内容的清洗，但更高杠杆的操作是**在获取阶段就过滤掉劣质信源**——不是先抓一堆垃圾再脱水，而是从源头只抓有营养的东西。

**典型案例**：要求 Agent 调研某校考研复试线。若放任 Agent 在公开搜索结果中自由点击，它会被培训机构广告、自媒体预测、登录墙和 SEO 文章淹没（体 28 硅基注意力平权缺陷），最终从噪音中"缝合"出一个伪完成结果。而正确路线是：先锁定官网 → 优先定位 PDF/附件/官方通知 → 再做结构化抽取。

**信源三层漏斗**：

1. **L1 权威源锁定**：在搜索指令中显式限定域名白名单（如 `site:xxx.edu.cn`）或信源类型（官方公告、政府文件、一手数据库），物理排除自媒体与商业站点
2. **L2 载体优先级**：同一权威源内，优先提取 PDF 附件 / 结构化数据表 > 正文网页 > 新闻转载。PDF 附件通常是最终确认版，网页正文可能滞后或不完整
3. **L3 脱水清洗**：仅在通过 L1/L2 筛选后的内容上执行脱水，将其压缩为无感情的 Markdown 事实表

> **先收窄信源再脱水内容，是"体 28 + 体 27"的组合解。让 Agent 在垃圾堆里找金子，不如一开始就只让它进金矿。**

## 战区二：LLM 引擎轴（算力压榨与容错拦截）
> **战略目标**：利用算力通缩，对抗错误复利与幻觉。绝不顺着机器旧有的错误去微调，而是拔高准星做暴力重构。

### 用 01｜Regenerate > Modify（重造优于修补）

**源自**：体 13（算力通缩）+ 体 04（幻觉不可消除）

**战略逻辑**：

- 当生成成本远低于修改成本时，在 AI 产出的复杂逻辑树中人工排查并打补丁，等于用最宝贵的资源（注意力）去做最廉价的事情（生成）。
- 修补 AI 代码还引入交叉污染风险——人类的修改嵌入 AI 的逻辑链，破坏了整体一致性（体 04）。

**战略目标**：将错误处理从"Output 端打补丁"迁移到"Input 端优化约束"，实现非对称杠杆收益。

**边界条件（概率思维）**：

- **全量重造阈值**：测试通过率 < 50%，或存在根本性架构偏差 → 全量 Regenerate
- **增量精修阈值**：测试通过率 > 70%，仅少量边界未覆盖 → 增量约束补充 + 局部重生
- **不可逆副作用保护**：涉及外部系统状态（如数据库迁移已执行），Regenerate 前必须确认可回滚

**方向 vs 细节的快速判断流**：

- 80%+ 正确 + 少量细节问题 → 3 轮 Prompt 内可修复 → **继续推进**
- 80%+ 正确但大方向跑偏 → **在确认无需保留本地未提交修改的实验分支 / 沙盒 Worktree 中，立刻 `git reset --hard HEAD` 回到上一次提交**，修改 Spec 后重新生成

---

### 用 05｜链头防御优先

**源自**：体 10（错误叠加复利）

**战略逻辑**：

- 在多步骤 Agent 流水线中，早期错误修复成本是后期的指数倍。**链条启动前投入验证，是单位时间回报率最高的操作**。
- 不要把反复推敲 Spec 视为"拖延"——那是流水线中信噪比最高的工作。

**战略目标**：在 Agent 链启动前穷尽所有可见约束漏洞，让错误只在"纸上"发生。

---

### 用 06｜谄媚免疫

**源自**：体 08（谄媚幻觉）

**战略逻辑**：

- 永远不以"AI 说它完成了"作为任务结束标准。AI 的自我汇报存在系统性高估偏差。
- 建立"零信任验收"：自动化测试的绿灯只代表 **LLM 执行阶段完成**，不代表任务可直接合并。
- 测试全绿后，任务才有资格流入 AI/人类二次审阅；任一审阅未通过，返回重生链路。
- 当你想施压（"你确定吗？再想想"）时，要警惕——你可能正在触发谄媚漂移。

**战略目标**：先用确定性机器验证截断 LLM 阶段，再用 AI + 人类审阅制度决定是否合并，从制度层面消灭"感觉上是对的"。

**失效子模式：伪完成（Pseudo-Completion）**

谄媚幻觉在 Agent 场景中存在一种更隐蔽、更危险的变体——**伪完成**：Agent 并非完全无法执行任务，而是为了闭环，给出一个"看起来相关但不满足任务定义"的结果。

**典型案例**：要求 Agent 查询南昌大学 2025 考研复试线。Agent 未能稳定进入官方源和附件/PDF 主战场，被搜索噪音（培训机构、自媒体、登录墙）干扰，最终用"相关但不直接回答问题"的信息交差——比如返回往年分数线、招生简章摘要或培训机构的预测文章。表面上任务闭环了，实质上核心数据缺失。

**伪完成识别标准**：

1. **答非所问检测**：输出是否精确命中了任务定义中的核心字段（如"2025年、具体专业、官方复试线数字"），而不是周边相关信息
2. **信源溯源检测**：输出引用的来源是否为任务要求的权威源（官网/官方PDF），还是被搜索引擎噪音替代
3. **闭环假象检测**：Agent 的自我汇报是否使用了模糊收尾词（如"综合来看""根据相关信息"），而回避了"未找到"的诚实声明

> **伪完成比明确失败更危险——它消耗了你的信任预算，却没有交付真正的结果。对调研类任务，验收标准必须包含"核心字段是否精确命中"的硬校验，而非"看起来回答了"的软印象。**

### 用 12｜全面协同推理化

**源自**：体 17（推理红利压制定律）

**战略逻辑**：
- 当更优秀的工具底座已然颠覆生态边界，我们就应当系统性抛弃传统低级别提示词在微观细枝末节的无聊修正；既然要解决难题就应当毫不妥协。
- 对多数具备强因果逻辑、大面积构建且具极强深度拓扑关系的结构推演，将底层引擎统一切换并固化于长线推理模型（System 2 类）。

**战略目标**：将所有涉及核心规划、重构解耦、架构设计的主线逻辑流全部强制交由于推理型基座直接介入，放弃小差距带来的妥协。

---

### 用 15｜进化论式多轨择优

**源自**：体 19（生成廉价法则）+ 体 10（错误叠加复利）

**战略逻辑**：
- 在单线长会话中，当 AI 跑偏超过 20% 时，若是继续用自然语言反复指责、逼迫其在原框架上修 BUG，极易让大模型陷入智商降级的自我死循环（往往带来更高的重构风险与时间沉没成本）。
- 既然生成已是零代价廉价算力，最经济强大的做法就是修改顶层系统指令，清爽重开新沙盒。

**战略目标**：以"物竞天择"的上帝视角代替"缝缝补补"的包工头心态。重开优于纠缠，多开优于单死磕。

### 用 15b｜反馈通道工程战略（模糊→精准反馈转化）

**源自**：体 39（反馈即维度桥接）+ 体 38（维度不可压缩）+ 体 04（幻觉不可消除）

**战略逻辑**：
- 体 39 揭示：幻觉的根因是反馈真空，而非模型不够强。因此，**系统优化的最高杠杆点不是写更好的 prompt，而是为每个关键维度铺设精准的反馈通道**。
- 现实中大量反馈是"模糊"的——人类看一眼觉得"差不多"、日志里淹没了几万行无关输出、报错信息指向框架内部而非业务逻辑。模糊反馈 ≈ 无反馈，因为 LLM 无法从中提取有效纠偏信号。
- 反馈工程的核心任务是：**用确定性工具将模糊的现实维度信号转化为 LLM 可直接消费的精准结构化反馈**。

**反馈通道铺设清单**：

| 目标维度 | 模糊反馈（低价值） | 精准反馈（高价值） | 转化工具 |
|---|---|---|---|
| **形式逻辑正确性** | "代码看起来对" | 编译器 / 类型检查器的 0/1 通过信号 | TypeScript `tsc --noEmit`、Rust `cargo check` |
| **行为正确性** | "跑了一下好像没问题" | 单元测试 + 集成测试的 PASS/FAIL + 覆盖率 | pytest、vitest、Playwright |
| **接口契约合规** | "返回值大概对" | Schema 校验器的结构化 diff | JSON Schema validator、Pydantic、Zod |
| **运行时状态** | "日志太长看不完" | 经过过滤截断的关键错误帧 + 结构化堆栈 | 日志过滤脚本、`grep -A5 ERROR`、Sentry 结构化告警 |
| **性能维度** | "感觉有点慢" | 基准测试的量化数字（延迟 ms、内存 MB、QPS） | benchmark 框架、`time` 命令、profiler |
| **事实准确性** | "搜索结果一大堆" | 权威源精准命中 + 脱水事实表（用 23） | 信源三层漏斗 + Flash 脱水管道 |
| **业务语义** | "产品说不太对" | 验收用例的结构化 Given-When-Then 断言 | BDD 框架、人类审阅 checklist |

**反馈质量四象限判断**：

- **精准 + 高频**（编译器、类型检查）→ 最强反馈，LLM 自闭环效率最高
- **精准 + 低频**（人类 Review、集成测试）→ 有效但昂贵，用于链尾验收
- **模糊 + 高频**（冗长日志、未过滤搜索结果）→ **最危险：看似有反馈，实际是噪音注入**，必须先转化再喂入
- **模糊 + 低频**（"感觉还行"的主观印象）→ 等于无反馈，必须用工具替代

**战略目标**：为系统中每一个可能产生幻觉的维度铺设至少一条精准反馈通道。将"人类肉眼看一遍"的模糊反馈，系统性地替换为"确定性工具输出结构化信号"的精准反馈。反馈通道的密度和精度，就是系统可靠性的天花板。

### 用 19｜推迟决断与保持最高开放度

**源自**：体 20（指令僵化悖论）+ 体 22（过早优化塌陷陷阱）

**战略逻辑**：
- 不要在早期追求编写长篇大论的细节 SPEC，那会引发 AI 的瀑布流开发灾难与批量错误复利。
- 保留设计的可回滚状态，仅设定边界，在边跑边测试的过程中，通过“多路抽卡”让大模型去验证各种实现的细节。

**战略目标**：用“边做边测试”的涌现式探索取代“开工前万全设计”的呆板指挥。

### 用 24｜职责物理分层（任务专一战略）

**源自**：体 18（硅基注意力负载）+ 体 02（Agent 三元结构）

**战略逻辑**：
- 任务越复杂，LLM 的单位注意力价值越低。将“搜索获取”、“提炼脱水”、“对比推理”混在同一个模型调用中，会因上下文负载过重导致逻辑降级。
- 通过流程拆分，让每个模型只干一件极其纯粹的事，能大幅提升系统的总信噪比与确定性。

**战略目标**：建立物理分层管道。检索模块只管叼回骨头，脱水模块只管剔肉留骨，推理模块只管嚼骨吸髓。通过职责分层，实现推理质量的越级提升。

### 用 24b｜任务形态路由战略（比较优势分工）

**源自**：体 28（硅基注意力平权缺陷）+ 体 31（最小闭环优先）+ 体 37（连续性坍塌与跨模态补偿）

**战略逻辑**：
- 不同任务类型对"行动能力"与"判断能力"的依赖比例完全不同。将所有任务无差别丢给同一种工具形态（全用 Agent 或全用对话），是对比较优势的系统性浪费。
- **Agent 的比较优势是"能动性"**：擅长跨工具编排、代码执行、文件操作、多步骤构建——即需要"手脚"的任务。
- **Deep Research 的比较优势是"判断性"**：擅长检索、比对、综合、证据链构建——即需要"眼脑"的任务。
- 当把调研类任务交给 Agent 时，它倾向于用"行动"来弥补"判断"的不足——疯狂点击、跳转、抓取，却因体 28（注意力平权）被搜索噪音淹没，最终滑入伪完成（用 06）。

**典型案例**：Excel 智能操作的路线选择。讨论中明确了行业主流不是"像人点击 GUI"（Agent 路线），而是"绕过 GUI，直接操作对象模型/模板"（工程路线）。这说明即使在看似需要 Agent 的场景中，真正的比较优势往往属于专业工具 + LLM 规划的混合架构，而非端到端 Agent。

**任务形态路由决策表**：

| 任务特征 | 推荐形态 | 原因 |
|---|---|---|
| 需要检索、比对、证据链、综合判断 | Deep Research / 检索+脱水管道 | 判断 > 行动，Agent 在开放搜索中极易被噪音淹没 |
| 需要代码执行、文件操作、多工具编排 | Agent（Cursor/Manus） | 行动 > 判断，Agent 的工具闭环能力碾压纯对话 |
| 需要精确的局部控制、定量操作 | 专业工具（Excel 对象模型/Photoshop）+ LLM 规划 | 确定性 > 语义灵活性，LLM 做规划、专业工具做执行 |
| 需要语义级创意、风格探索、方案发散 | LLM 原生对话 / 生成模型 | 发散 > 收敛，不需要工具介入 |

> **不是所有钉子都该用锤子。Agent 是好锤子，但调研需要放大镜，精确编辑需要手术刀，创意探索需要画笔。先判断任务的核心能力需求（行动/判断/精确/发散），再选择对应的工具形态。**

## 🛠️ 战区三：Tools & Instruction 轴（元指令与手脚控制）
> **战略目标**：对抗指令干涉和技术栈冲突摩擦。严格控制 Agent 身上的外挂与 SOP 指令重量，不被伪需求拖垮。

### 用 08｜指令正交治理

**源自**：体 12（指令干涉）+ 体 05（信噪比衰减）+ 体 14（工具动态演进）

**战略逻辑**：

- Skills、AGENTS.md、MCP 工具的底层全是注入上下文的指令 Token，错误指令会系统性扭曲所有输出。
- 必须对指令层施加与代码架构同等严格的治理。

**五项治理原则（反细化狂热）**：

1. **正交原则**：任意两个 Skill 的职责域不得交叉覆盖
2. **单一职责原则**：每个 Skill 只做一件事
3. **通用能力优先且克制碎片 MCP**：放弃对超细粒度操作控制的偏执。只要能提供能给 Agent 直接自闭环的通用底座环境（如 Bash 控制台、Python 裸执行器），就坚决不写一百个繁琐死板的特定 API 工具。授予图灵完备权力永远胜过戴着镣铐跳舞。
4. **常识免教学原则（零废话）**：任何早已成为主流大模型前向预训练集内的固有基础范式（如框架的起步样板、通用架构构成），绝对禁止在系统技能中再以字面教导。教神兽认字是对系统首位 Token 算力池的无情挥霍。
5. **定期断舍离**：旧时代的复杂约束随着模型基建升级，必须以季度为单位斩除清空。

**运行时装载规则**：

- **全局层最小化**：`AGENTS.md` / `.cursorrules` 只保留跨任务、跨项目都成立的最小宪法，不把整本框架直接挂进运行时
- **任务层按需挂载**：单次任务默认只加载 1-3 个正交 Skill / MCP，优先少而准，拒绝全家桶
- **冲突先降载**：一旦两个 Skill 在同一职责面给出重叠指导，先卸载其一，再继续执行；禁止让模型在冲突指令中概率折中

**战略目标**：像管理微服务架构一样管理指令系统——正交、解耦、按需加载、定期清理死代码。

### 用 22｜动态 SOP 调度战略（免教与强控）

**源自**：体 25（SOP 效用相对论）+ 体 24（域不对称定律）

**战略逻辑**：
- 既然 AI 内置的神经网络权重在特定碾压领域已经远超我们能用文字外置描述的上限，那么“写冗长的指示手把手教它怎么做”就已经演退成了一种系统摩擦损耗。
- 通过识别当前任务的优势归属，彻底切分控制台模式：在 AI 的绝对主场中发挥其“黑盒神迹效应”，让其奔跑；在 AI 的客场中强行套上“人类结构化模具”。
- 运行时调度必须显式分层：全局层保留最小宪法，单域编码任务默认进入“免教模式”并最多挂载 0-1 个领域 Skill；复合域 / 高风险域进入“强控模式”，但仍限制在 1-3 个正交模块内，避免再次膨胀成指令泥石流。

**战略目标**：实施极端的两极管管辖模式。在代码生成与单点逻辑推演等 AI 胜出域，彻底废除步骤级的啰嗦 SOP 与低效的外围知识库指令干预，直接“目标导向”呼唤其巅峰算力；在投资权衡、架构决断等人类胜出的复合域，绝不给其自由散漫的发散度，强制启动极其死板严密的排爆式 SOP 以死死卡住它的推演底线。

## 👑 战区四：Human 轴（统帅部边界与注意力防线）
> **战略目标**：保卫单线程人类生物脑瓶颈，对决复合能力不对称晕轮。将人类极其有限的高维算力全部押注在“画框与拍板”上。

### 用 02｜契约前置

**源自**：体 04（幻觉不可消除）+ 体 05（信噪比衰减）

**战略逻辑**：

- 允许 AI 在无明确边界时同时处理 UI、业务逻辑和数据库，多目标冲突极大概率触发幻觉。
- 通过开工前锁定 API 规范、数据模型和接口约定，用"接口宪法"强行圈定 AI 的精准沙盒。

**战略目标**：通过前置契约，将 AI 的"自由创造"降维为确定性范围内的"填空"行为。

**Spec 弹性区间原则（约束锁死、路径留白）**：

> 过度详细的 Spec 等同于把代码实现写出来了，不仅消耗人类注意力（体 03），还限制 AI 找到更优方案的空间。实战证据表明，给予高层方向 + 验收标准时，AI 有时能产出超越人类预期的优雅方案（AlphaGo 第 37 手效应）。

- **边界层：绝对锁死** — 针对外部黑盒通信、数据模型、API 接口，必须严格契约前置（防幻觉）
- **实现层：绝对留白** — 针对内部函数实现、推演逻辑，不告诉 AI "怎么做"，只告诉"不能做什么"和"终态是什么"（给模型发散寻路空间）
- **粒度锚定**：约 1000 Token Plan 对应约 500 行代码改动

### 用 03｜守护人类注意力

**源自**：体 03（人类认知本质）

**战略逻辑**：

- 人类注意力是系统中最稀缺的资源（体 03）。当 Multi-Agent 系统高速运行时，如果底层噪音不受限制地上浮，系统总效率被人类这个"最慢节点"锁死。
- 一切工程优化的终极目标：最小化人类被打扰的次数，最大化每次介入的杠杆率。

**战略目标**：建立注意力防火墙，在 Agent 系统与人类之间设立物理隔离层，只允许高信噪比的信号穿透。

### 用 16｜克制型 SPEC 与就近背景

**源自**：体 20（指令僵化悖论）+ 体 06（深广不可兼得定律）

**战略逻辑**：
- 拒绝旧时代瀑布流那动辄几千字的伪敏捷“过度设计大词典”。
- 写 SPEC 只需要把死守的终局验收标准画框，把绝对不能触碰的高压线列出。具体的实现探索权百分百下放给大模型自己用发散算力寻路。
- 为什么不写在一个远端系统设计文档里？因为让模型去查库就是巨大的“查找损耗”。背景理念应该顺手埋进长函数名或顶头上方的备注里，保证极简极快读取。
- **但就近背景只承担执行层的检索辅助职责**：它负责“方便找到、方便理解”，不负责篡改全局目标。全局目标与硬约束始终以上位 `spec.md` / `constraints.md` 为准。
**战略目标**：实现 SPEC 反向缩水。将全局目标上收到 `spec.md` / `constraints.md`，将执行层背景下沉为就近命名与注释，以小范围框定防爆 + 就近代码解释维持高信噪比。

### 用 20｜单兵全栈闭环战略

**源自**：体 23（对齐损耗定律）+ 体 13（算力通缩）

**战略逻辑**：
- 既然 Agent 可以承接跨端（前后端/测试/运维）的脏活累活，人类架构师就不应再按传统的职能划分切片。
- 人类应从“全能指挥”进化为“单点督战的导演”。一个人+一群 Agent，必须从产品需求直达上线闭环。

**战略目标**：消灭一切人与人的进度排期依赖。一个人能闭环的业务上限，只等同于其“Review 全链路代码的审美边界”。

### 用 21｜复合领域防盲信与人机分权战略
 
 **源自**：体 24（单域与复合域能力不对称定律）+ 体 26（信息不平权与观察窗不对称定律）+ 体 04（幻觉不可消除）
 
 **战略逻辑**：
 - 因为 AI 在写代码等单线上表现出了“神迹”，人类极易产生致命的“晕轮效应”，将投资方向、架构生死抉择等复杂权衡的判断权也盲目下放给 AI。
 - 在复合领域里，许多看似是“谁更强”的争论，本质上只是信息窗不对称：AI 可能掌握通用模式，人类掌握隐性约束、现实后果与未文档化背景。若不先校准信息面，就会把“信息差”误判成“能力差”。
 - 因此，进入判断前的第一动作不是追问结论，而是先检查当前信息是否足以支撑下一步：目标是否清楚、约束是否完整、关键事实是否齐备。缺事实就查证，缺约束就外化，缺验证就实验，缺不齐就显式标注假设后小步推进。
 - 在复合领域，AI 的最大价值是“穷举可能性”、“提供反常识视角”或“搜集整理基建信息”，而绝不是“下结论”。最终的果断拍板，往往依赖人类长期的默会知识与直觉。
 
 **战略目标**：先校准信息面，再划分判断权。单领域（编程实现、数据清洗）在信息充分时彻底放权闭环执行；复合领域（投资规划、战略路线）则由人类掌握最终判断权，AI 降维为负责补信息、提反例、做穷举和提供信息弹药的高阶数据参谋。

### 用 25｜容错滑动变阻器战略（风险驱动的资源配平）

**源自**：体 29（确定性守恒定律）+ 体 24（单域与复合域能力不对称定律）

**战略逻辑**：
- 在启动任何任务前，架构师的第一动作不应是写 Prompt，而是**评估该任务的“物理破坏力”与“容错底线”**，并据此拨动 `LLM : (Memory + Tools)` 的分配推子。
- 绝不能用同一套“最佳实践”去打天下。用重型工程管理去写一个内部脚本是浪费算力，用纯 LLM 自由发散去改写资金清算逻辑是自寻死路。

**配平参数面板**：

1. **L0 毁灭级（0 容错：删库、资金、越权）**：`Tools(90%) + Memory(90%) + LLM(10%)`
   - 战略：人类 100% 批准，极其苛刻的沙盒防线，将 LLM 降维为纯文本转换器，剥夺一切业务实现权。
2. **L1 生产级（低容错：核心业务流、对外 API）**：`Tools(60%) + Memory(60%) + LLM(40%)`
   - 战略：契约前置（用 02），测试驱动（术 02），在锁死的边界内允许 LLM 填充逻辑。
3. **L2 实验级（高容错：UI 还原、数据清洗、内部工具）**：`Tools(10%) + Memory(10%) + LLM(90%)`
   - 战略：免教模式。拆除一切冗长规范，一句话目标导向，靠大模型原生权重与廉价算力暴力重试（Regenerate）寻优。

**战略目标**：放弃对“完美通用流程”的幻想。根据场景的死亡成本，动态调节防呆工程（护栏）与发散算力（引擎）的注入比例。
