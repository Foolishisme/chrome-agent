# Browser Agent 新线程现状

## 1. 文档定位

本文档描述“当前代码相对于新设计”的实际位置。

它不假设代码已经完成重构，而是明确指出：

- 哪些东西还能复用
- 哪些东西属于旧设计残留
- 下一步最小重构从哪里开始

---

## 2. 当前代码现实情况

当前代码仍然主要建立在旧主线之上：

- `scan -> llm -> act -> observe`
- LLM 仍参与较细粒度决策
- scanner 与提取逻辑耦合较深
- tools 仍偏细粒度 DOM 动作

已知可复用资产：

- MV3 工程骨架
- Side Panel 基础 UI
- Runtime 主循环框架
- 消息协议
- 页面 overlay
- 京东页面扫描与提取经验
- 基础测试与构建链路

---

## 3. 与新设计的差距

### 3.1 Tool 粒度不对

新设计要求：

- LLM 调度高阶 tool

当前代码实际：

- tools 更接近底层动作层
- 组合逻辑分散在 runtime、scanner、actions 之间

### 3.2 LLM 介入过早

新设计要求：

- LLM 负责规划、调度、最终结果

当前代码实际：

- LLM 仍处于主执行链中
- 很容易被页面噪音和中间状态带偏

### 3.3 scanner 与 extractor 未彻底分层

新设计要求：

- 页面扫描负责事实
- 结构化提取由独立 tool 完成

当前代码实际：

- scanner 已经承担了较多结果提取职责

### 3.4 Runtime 边界仍偏重

新设计要求：

- runtime 负责循环、状态、校验、容错

当前代码实际：

- runtime 仍承载较多业务推进细节

### 3.5 结果渲染仍偏固定

新设计要求：

- 前端渲染 Markdown 或通用结果块

当前代码实际：

- 前端仍以固定表格字段为主

---

## 4. 当前可直接复用的模块

可以优先保留并重构的模块：

- `src/background/runtime.ts`
  - 保留循环框架，但要改成 tool-first
- `src/content/overlay.ts`
  - 可直接复用
- `src/content/scanner.ts`
  - 可保留页面事实扫描部分
- `src/content/actions.ts`
  - 可下沉为底层原子动作
- `src/shared/*`
  - 可复用类型、协议、常量基础
- `src/sidepanel/index.ts`
  - 可保留控制面板骨架，但结果区要泛化

---

## 5. 当前建议废弃或弱化的思路

优先废弃或弱化：

- 让 LLM 决定细粒度 DOM 动作
- 把 scanner 当作主要业务提取器
- 在主 loop 中频繁请求 LLM
- 让 runtime 处理过多站点级脏逻辑

---

## 6. 第一轮最小重构目标

新线程的第一轮目标不应该是“全部重写”，而应该是：

1. 定义高阶 tools 接口
2. 把底层 DOM 动作沉到原子层
3. 把搜索、提取、过滤封成组合 tool
4. 把 LLM 从细粒度 loop 中后移
5. 把最终结果改成 Markdown 输出

---

## 7. 当前验证状态
