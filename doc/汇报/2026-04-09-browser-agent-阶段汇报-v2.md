# Browser Agent 阶段汇报

更新时间：`2026-04-09`

---

## 一、它能做什么

Browser Agent 是一个 Chrome 浏览器插件。用户在侧边栏用自然语言提问，Agent 自动理解意图、操控浏览器完成搜索和信息采集，最终交付结构化的结果。

当前已跑通三类任务：

### 1. 商品搜索与推荐

用户说："帮我找一款 500 元以内的降噪蓝牙耳机"

Agent 自动打开京东、输入搜索词、提取商品列表、按条件过滤，最终输出一份结构化的商品推荐。

### 2. 公网调研

用户说："2026 年主流的前端框架有哪些，各自优劣是什么"

Agent 自动用 Google 搜索、从第一页筛选高质量来源、逐个打开阅读提取关键信息，最终汇总为一份调研报告。

### 3. 知识问答

用户说："解释一下什么是事件循环"

Agent 判断无需搜索，直接给出结构化回答。如果用户之前搜过相关资料，还能基于已有证据追问。

**与 Manus 的定位差异**：Manus 是云端通用 Agent，面向开放任务；我们是浏览器原生插件，聚焦"搜索、阅读、交付"这条垂直链路，不走通用路线，优先把这条链打透。

## 二、做到什么程度了

### 一句话概括

Agent 的骨架已经搭起来了。三条主链能跑通，核心架构已收口，但每一层还需要继续打磨才能稳定交付。

### 具体进展

| 维度 | 当前状态 | 说明 |
|---|---|---|
| **核心链路** | 已跑通 | 商品搜索、公网调研、知识问答三条链路均已在真机验证通过 |
| **决策能力** | 基本具备 | Agent 能区分"该搜索还是直接答"、能根据用户偏好调整策略 |
| **执行引擎** | 已收口 | 统一的计划执行循环，不再是硬编码的脚本流程 |
| **连续对话** | 基本具备 | 支持多轮追问，能复用前几轮的搜索结果作为背景 |
| **会话管理** | 基本具备 | 支持新建、切换、删除会话，支持回退到历史轮次 |
| **运行护栏** | 已落地 | 超时自动停止、连续失败自动停止、用户可手动停止 |
| **自动化测试** | 84 个测试通过 | 覆盖核心链路、契约、护栏和 UI |

### 上周演示后的新增

- 搜索偏好开关：用户可切换"智能回答"和"优先搜索"模式
- 直接回答能力：简单问题不再强制打开浏览器搜索
- 调研来源重排序：第一页搜索结果会经过轻量排序，优先读高质量来源
- UI 收口：对话流统一展示、结果区精简、历史会话管理

## 三、接下来的安排

### 当前阶段判断

下一步不是继续堆更多新功能，而是把已有链路打磨到更稳定、更可用的程度。

原因很简单：如果骨架没长实，功能面越扩，后面返工成本越高。

### 下一个里程碑目标

**让 Agent 从"能跑完"走向"能交付"。**

需要优先补强的核心能力：

| 优先级 | 方向 | 具体目标 | 预期效果 |
|---|---|---|---|
| P0 | 决策准确性 | 减少"该搜没搜"或"该直接答却绕路"的误判 | 用户体感更靠谱 |
| P0 | 结果交付 | 补齐结果下载和导出能力，结果格式更稳定 | 用户能带走一个可用的结果 |
| P1 | 用户个性化 | 支持全局 rules，让用户定义偏好、关注领域和输出风格 | Agent 越用越懂用户，决策和输出更贴合个人需求 |
| P1 | 网页资料下载 | Agent 在调研过程中可下载网页中的文档、PDF、图片等附件 | 不只是文字汇总，还能把原始材料带回来 |
| P1 | 结果图表渲染 | 前端支持渲染 Mermaid 流程图和 SVG 图表 | 调研和对比类结果更直观，交付质量感知显著提升 |
| P1 | 对话记忆 | 多轮对话中对已有证据的复用更稳定 | 连续聊几轮后仍然知道自己为什么这么答 |
| P1 | 运行体验 | 执行过程更可见、异常更可理解 | 用户能放心看它执行，需要时能接管 |
| P2 | 文件上传 | 支持用户上传文件作为任务输入，Agent 可基于文件内容搜索或分析 | 打开新的输入模态，不再只靠文字提问 |
| P2 | 多模型支持 | 验证 Gemini 和 DeepSeek 等不同模型的兼容性 | 降低对单一模型的依赖 |

### 明确不优先做的事

- 让 Agent 执行下单、支付等高风险操作
- 做通用的多站点适配器
- 做完整的长期记忆系统
- 继续堆更多 demo 站点（如支持淘宝、支持百度等）

## 四、风险与不确定性

| 风险项 | 影响 | 当前应对 |
|---|---|---|
| 搜索结果页结构变化 | 提取可能失效 | 已有局部恢复机制，但需要持续维护 |
| 模型 API 稳定性 | 执行可能中断 | 已有超时和重试护栏，但未做多模型联调 |
| 复杂问题误判路由 | 用户体感不佳 | 已有偏好开关，但需要更多真实样本收敛 |

---

## 附：技术架构一句话

```
用户输入 → Agent 理解意图并生成计划 → 自动操控浏览器执行搜索/阅读 → 结构化交付结果
```

底层遵循 `Agent = LLM + Tools + Memory + Runtime` 的标准 Agent 架构，和 Manus 等产品的核心范式一致，但在浏览器原生场景做了针对性的工程取舍。
