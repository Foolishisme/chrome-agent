# Browser Agent 交互设计规则

## 1. 文档定位

本文档只回答一件事：当前主线下，系统应如何被用户理解、等待、信任和接管。

它定义：

- 产品表达原则
- Side Panel 上下文与层级
- 过程与结果的默认关系
- 状态准入与控制防呆逻辑

它不记录：

- runtime / tool 协议细节
- 当日实现进度
- 视觉样式微调

## 2. 当前目标

当前交互层的首要目标不是“展示系统功能全知全能”，而是：

- 让用户在任一时刻只处理一个主问题
- 保证复杂执行过程的高度收敛，最终交付物独立、连贯、且唯一
- 让等待过程可见且清晰，但不过载页面空间
- 让错误、阻断和边界情况可明确获知并可接管

## 3. 表达原则

### 3.1 视觉留白与空间收敛

界面必须优先服务当前的交互意图，不再预留静态的各类“空区域”来争抢注意力。

当前规则：

- 新会话初始态屏幕大片留白，视觉焦点锁定在底部常驻输入区
- 每个指令请求及其结果被封装在统一且独立的 Turn（轮次流）里
- 指令生命周期闭环后，终态结果在归属的 Turn 内部完成呈现，不扩散

### 3.2 最终正文唯一

最终交付物必须在对应的 Turn 结构中唯一存在，避免过程流与结论同时裸露带来“系统复读”的错觉。

当前规则：

- 单个 Turn 生成的最终正文（inline）在结果部分渲染一次
- 导出产物（artifact，如文档卡片）隶属于该交付结果中，单独标记下载或查看，非第二份等价正文
- 状态操作与正文显示严格分层
- 概况型调研结果默认标注读取范围、覆盖边界与未覆盖区域，不伪装成精准确认

### 3.3 过程可见但次于结果

用户必须随时能看到系统“正在做什么”，但呈现层级必须低于最终交付结果。

当前规则：

- 运行中默认展开呈现当前步骤的摘要及时间线（Timeline）
- 等待过程结束后，时间线自动折叠，收束注意力至交付的结论
- 日志（logs）、工具明细（debug）属于次级下翻探索项，永远默认折叠

### 3.4 输入引擎代表当前 Draft

输入框及其伴随的控件仅仅是下一次交互的草稿（Draft），不被系统的历史记录“绑架”。

当前规则：

- 历史会话内容不会反向回填覆盖当前的输入框
- 运行中状态的变化不应覆盖输入框正在打字的本地文本
- 占位文案只是视觉缓冲，并非已提交文本
- 输入框旁附属的开关（如：智能回答 / 优先搜索）仅表示下一次启动的任务参数偏好选项

### 3.5 状态准入与防呆控制

自动化接管的各个阶段必须让用户清晰知道“操作权在谁手里”，避免误操作或阻断带来的无力感。

当前规则：

- 空闲态给予完全发送畅通路径，支持热键操作（如回车送出、发送图标）
- 运行中强制锁定主输入通道发起轮次的能力，并提供唯一显式的 `中断/停止` 通道
- 任务执行完毕或直接遇阻，输入引擎立即释放，重新接管下一轮通信
- 高风险状态与无法突破的隔离墙，需在出错 Turn 内呈现直接错误提示

### 3.6 等待焦虑降级

系统对进度缓冲有客观标准，避免前端装死或自慰式展示进度条。

当前规则：

- 执行期间全程强制暴露当前正在执行的任务层级、阶段流转状态以及累计执行耗时
- 护栏拦截与抛出异常时需要给到对应的结构化展示出口
- 不靠快速刷屏的底层字符输出去掩盖系统实质死循环或无进展情况

## 4. 当前 UI 结构范式

Side Panel 整体以 `连续 Turn 流` 模型为基座展开界面构建：

1. **抽屉/全局非主视区**：收纳管理与本界面的弱关联信息，如历史会话（Conversation）列表。
2. **主流程滚动区（Turn Stream）**：
   - 顶部罗列本会话内过往的独立交互轮次（目标 -> 收折后的过程时间线 -> 闭环交付物）。
   - 底部衔接着正在运行中的活跃轮次（实时状态/进度更新）。
3. **下部锚定操作引擎**：紧贴底部的一体化用户输入指令草稿与侧沿首选项开关（Draft 区）。

## 5. 当前明确不做

基于最新底层约束，前端展现依旧严禁以下设计：

- **拒绝无细节打磨的 Token 级流式展现**：不允许为了类似“聊天打字”而去引入高频刷新的内容碎片渲染，防止页面视觉撕裂破坏最终交付物的完整阅读连续感。
- **拒绝无结构的傻瓜式平铺聊天**：我们引入 Turn 的流式呈现，但是绝不把执行动作、组件提取报错等细节混入类似对话流式的“泡泡”消息中平铺堆砌。
- **拒绝前端越权裁量执行路由**：搜索偏好开关仅属对 LLM 启动环境的提示缓冲，最终问题如果极为简单或已知界限明确，“需要回答还是必须去网页搜索”不由该轻量开关做绝对独断。

## 6. 后续扩展约束

若未来交互体系演进将支持更跨会话边界的长记忆，同样需继承当下的基本底线：

- 单次生成的最新有效交付在心智层级上永久保持绝对最高权重。
- 从来都不是把过去的冗余状态杂糅进新的任务操作流里；历史资产的查询利用应当继续用抽屉折叠等形式完成物理层面的界面让渡。
- 只有能充分自证“所加界面层不造成任何噪音反弹”的新功能状态才被准许添加到当前的单一 Turn流 展现区。
